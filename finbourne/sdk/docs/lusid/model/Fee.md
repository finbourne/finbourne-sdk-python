An arithmetic expression (+, -, *, /, numeric literals) over data points from the valuation point being calculated and from the previous valuation point (via the \&quot;Previous.\&quot; prefix; these resolve to zero at a fund&#39;s first valuation point). All values are in the fund currency unless stated otherwise. When the Fee is a NonShareClassSpecific Fee (i.e: when ShareClasses contains no values), the available data points are: \&quot;GAV\&quot;, \&quot;NAVPreFees\&quot; (GAV adjusted for external fees, before any fee accruals), \&quot;Amount\&quot; (the previous valuation point&#39;s NAV), \&quot;Dealing[dealingFilterId]\&quot;, \&quot;BackOut[backOutFilterId]\&quot;, \&quot;PnL[pnlFilterId]\&quot;, \&quot;ExternalFees[externalFeeFilterId]\&quot;, \&quot;Fees[feeCode].Amount|TotalAccrual|PreviousTotalAccrual|CalculationBase\&quot;, \&quot;Properties[Fund/scope/code]\&quot; (numeric, non-derived fund properties), and under the \&quot;Previous.\&quot; prefix: \&quot;Previous.GAV\&quot;, \&quot;Previous.NAV\&quot;, \&quot;Previous.Dealing[id]\&quot;, \&quot;Previous.BackOut[id]\&quot;, \&quot;Previous.PnL[id]\&quot;, \&quot;Previous.ExternalFees[id]\&quot; and \&quot;Previous.Fees[feeCode].Amount|TotalAccrual|CalculationBase\&quot;. \&quot;GAV\&quot; is the gross asset value before any external fees, whereas \&quot;Previous.GAV\&quot; is the previous valuation point&#39;s reported GAV, which is after any external fees that apply to a PnL bucket; for a like-for-like period comparison use \&quot;NAVPreFees\&quot; against \&quot;Previous.NAV\&quot;. \&quot;ExternalFees[id]\&quot; is the sum of the fund level external fees (positive amounts) and the share class external fees (booked as negative movements) matching the filter. Each id must be one the fund configuration defines: a filter id, or on a fund configuration with bucket sets, a bucket id of the apportionment bucket set of the matching bucket type (BackOut is not available with bucket sets). For example: \&quot;10000.00\&quot;, \&quot;GAV\&quot;, \&quot;GAV - Fees[FeeCode1].Amount\&quot;, \&quot;Previous.NAV - Dealing[Redemptions] + Dealing[Subscriptions]\&quot;. When the Fee is a ShareClass Fee (i.e: when ShareClasses contains at least one value), the same data points are available for the share class under the \&quot;ShareClass.\&quot; prefix (e.g. \&quot;ShareClass.GAV\&quot;, \&quot;ShareClass.Previous.NAV\&quot;, \&quot;ShareClass.Fees[FeeCode1].Amount\&quot;), with \&quot;ShareClass.PreviousNAV\&quot; as the previous NAV, plus \&quot;ShareClass.DealingUnits[id]\&quot;, \&quot;ShareClass.CapitalRatio\&quot;, \&quot;ShareClass.Previous.SharesInIssue\&quot;, \&quot;ShareClass.Previous.UnitPrice\&quot;, and the share class currency data points \&quot;ShareClass.ShareClassCcyGAV\&quot;, \&quot;ShareClass.ShareClassCcyPreviousNAV\&quot;, \&quot;ShareClass.ShareClassCcyNAVPreFees\&quot;, \&quot;ShareClass.ShareClassCcyGAVPreManagementFees\&quot;, \&quot;ShareClass.ShareClassCcyPerformanceFeeGAV\&quot;, \&quot;ShareClass.ShareClassToFundFxRate\&quot;, \&quot;ShareClass.PreviousShareClassToFundFxRate\&quot;, \&quot;ShareClass.Previous.ShareClassCcyGAV\&quot; and \&quot;ShareClass.Previous.ShareClassCcyNAV\&quot;. The expression must evaluate to a fund currency amount, so convert any share class currency data point explicitly, e.g. \&quot;ShareClass.Previous.ShareClassCcyNAV * ShareClass.ShareClassToFundFxRate\&quot;. \&quot;ShareClass.ExternalFees[id]\&quot; and \&quot;ShareClass.Previous.ExternalFees[id]\&quot; are both the external fees booked to the share class itself. Two pre-defined bases control the order fees are calculated in: fees are calculated in three tiers, and a fee&#39;s tier is fixed by its calculation base at creation. \&quot;GAVPreManagementFees\&quot; (NAVPreFees less the accruals of all Ordinary tier fees) makes the fee a Management tier fee, calculated after all Ordinary fees. \&quot;PerformanceFeeGAV\&quot; (NAVPreFees less the accruals of all Ordinary and Management tier fees) makes the fee a Performance tier fee, calculated last. Any other base makes the fee an Ordinary tier fee. Fees in the same tier see the same pre-defined base value regardless of creation order, so each pre-defined base is the value of the fund after all external fees and all earlier tier fees have been applied, and a fee cannot reference the accrual of a fee in a later tier. The ShareClass forms (\&quot;ShareClass.GAVPreManagementFees\&quot;, \&quot;ShareClass.PerformanceFeeGAV\&quot;) use the share class NAVPreFees less that share class&#39;s earlier tier fee accruals, including its capital ratio share of fund level fees; their share class currency forms (\&quot;ShareClass.ShareClassCcyGAVPreManagementFees\&quot;, \&quot;ShareClass.ShareClassCcyPerformanceFeeGAV\&quot;) put the fee in the same tier. No floor is applied to any calculation base: a negative base produces a negative accrual. |

| **fee_calculation_type** | **str** | Optional | How the Fee accrual amount is calculated. Available values: FixedAnnual, FixedDaily, FixedPercentage, VariablePercentage, Tiered, Blended. |
| **daily_accrual_amount** | **float** | Optional | The fixed daily accrued amount for a &#39;FixedDaily&#39; Fee, in the fund currency. The amount accrues for each day of the accrual period with no annualisation or day-count proration; Treatment does not affect it. |
| **variable_percentage_source** | **str** | Optional | The source of the rate for a &#39;VariablePercentage&#39; Fee, in the form \&quot;scope/provider/instrumentIdType/instrumentId\&quot; identifying a Rate quote series in the quote store. At each accrual date the most recent rate at or before that date is used; if no rate can be found the valuation point calculation fails. The quote&#39;s normalised value (its value divided by any scale factor) is applied like FeeRatePercentage, as a multiplier of the CalculationBase: a rate of 5.2% must normalise to 0.052. |
| **variable_percentage_source_offset** | **float** | Optional | An optional adjustment added to the rate resolved from the VariablePercentageSource, expressed as a factor like FeeRatePercentage (e.g. 0.0025 adds 25 basis points). |
| **tiers** | [List[FeeRateTier]](FeeRateTier.md) | Optional | The rate tiers for a &#39;Tiered&#39; or &#39;Blended&#39; Fee: between 2 and 10 tiers over the CalculationBase. Every tier except the last must have a Threshold, and thresholds must be positive and strictly increasing; a base equal to a Threshold falls in that tier, and the final tier covers the balance above the last threshold. A &#39;Tiered&#39; Fee applies the rate of the tier the whole base falls in; a &#39;Blended&#39; Fee applies each tier&#39;s rate to the portion of the base within that tier. |
| **fee_cap** | **float** | Optional | An optional annual cap on the accrued fee for &#39;FixedPercentage&#39;, &#39;VariablePercentage&#39;, &#39;Tiered&#39; and &#39;Blended&#39; Fees, in the fund currency and assessed period-to-date. Each day accrues only up to the amount left under the cap for the current fee year, which runs from one AnchorDate to the next; once the cap is reached nothing further accrues until the next AnchorDate. |
| **fee_floor** | **float** | Optional | An optional annual floor on the calculated fee for &#39;FixedPercentage&#39;, &#39;VariablePercentage&#39;, &#39;Tiered&#39; and &#39;Blended&#39; Fees, in the fund currency. The annualised fee amount is raised to the floor before being prorated to each accrual day. |
